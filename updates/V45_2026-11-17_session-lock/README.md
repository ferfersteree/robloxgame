# V45: замок сессии профиля (защита покупок при переходе между серверами)

Дата: 2026-11-17 · Файл места: `SpearHunt V45 - Session Lock.rbxl` (V44 плюс новый серверный `ServerScriptService/Server/Shop`; больше ничего не менялось)

## Проблема

Профиль игрока в DataStore (покупки, чеки, потраченные Robux для ранга, экзотики, осколки, очередь вылупления, снимок прогресса) писался через `SetAsync` по принципу «кто последний». Если игрок быстро заходил на второй сервер, пока первый ещё не сохранил, второй загружал устаревший профиль и при своём сохранении затирал свежее: терялись покупки и чеки (а потеря чека может повторно выдать товар). Это было записано в открытых делах («нет блокировки сессии профиля»).

## Что сделано

- Профиль помечается замком `lock = { id = <номер сервера>, t = <время> }`. Загрузка забирает замок и читает профиль одним атомарным `UpdateAsync`. Если замок свежий и чужой, игрок ждёт до 30 секунд, пока прежний сервер отпустит профиль (выход игрока), потом его мягко выкидывают с просьбой зайти через минуту (иначе он играл бы без сохранения).
- Сохранение тоже через `UpdateAsync`: если профиль за это время взял другой сервер, ничего не записывается и игрок просится перезайти (раньше затирал бы).
- Замок снимается при выходе игрока и при закрытии сервера; раз в минуту сервер подтверждает замок, даже если сохранять нечего; замок, который не обновлялся 3 минуты (сервер упал), считается брошенным и забирается.
- Старые записи без замка и хранилище без `UpdateAsync` (подмена в тестах) работают как раньше. В Studio без DataStore поведение прежнее.
- Проверочные крючки `Shop._test` дополнены: `setJobId`, `getJobId`, `setLockTimes`, `setKick`.

## Как проверено

- Новый тест `tests/session_lock.server.luau` на подменном DataStore с атомарным `UpdateAsync`: 23 проверки, все прошли (A занимает замок; B ждёт 5 секунд и сдаётся, не тронув запись; после выхода A загружается и видит данные A; замок старше TTL забирается; проигравший замок не перезаписывает и просит перезайти; старая запись без замка читается; повтор после двух сбоев; хранилище без `UpdateAsync`).
- Прежний `tests/eggs_persistence.server.luau`: 25 проверок, все прошли (прежний путь не сломан).
- Файл: отличается ровно текст одного модуля.

## Что не проверено

- Настоящий DataStore: в Studio к нему нет доступа. Использованы только документированные `UpdateAsync(key, transform)` с возвратом `nil` для отмены и массивом `UserIds`. Перед запуском с реальными игроками стоит включить Studio Access to API Services, опубликовать место и пройти вход с двух окон.
- Экономика игры по-прежнему считается на клиенте (`Config.BACKEND = "Demo"`): замок защищает то, что уже хранит сервер (покупки, чеки, экзотику, снимок), а не саму честность монет.
