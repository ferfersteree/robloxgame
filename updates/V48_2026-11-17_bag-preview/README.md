# V48: подпись «Bigger bag» с учётом бонусных мест; проверка покупок настоящими кликами

Дата: 2026-11-17 · Файл места: `SpearHunt V48 - Bag Preview.rbxl` (V47 плюс новый `Client/Menus`; больше ничего не менялось)

## Ошибка

В окне рынка строка улучшения сумки сравнивала общую вместимость (с бонусом ранга поддержки и питомцев) с базовой вместимостью следующего уровня. У игрока с рангом Gold и питомцем она показывала «Bigger bag: 95 → 45 slots», то есть улучшение выглядело как уменьшение. Это была открытая запись из списка дел («предпросмотр улучшения сумки не учитывает бонусные слоты»).

## Исправлено

Новая вместимость считается как текущая плюс прирост уровня: `bagCap + (cap следующего уровня − cap текущего)`. Проверено в Play: без бонусов 12 → 20 → 30 → 45 → 70 (как было); с рангом Silver (+20): «65 → 90», после покупки «90 → 120» (сходится с таблицей уровней 45/70/100 плюс 20).

## Инструмент

`tools/luau_names.py`: проверка имён без компилятора. Ищет имена, которые используются как `имя(`, `имя.` или `имя[`, но не объявлены в области видимости: опечатки и локальные функции, объявленные ниже места использования (в Luau это не ошибка при загрузке, а nil при вызове). Прогон по `source/` и `tests/`: 112 файлов, замечаний нет (один известный мёртвый код в `EggOpenings`: колбэки `fx.burst` там никогда не вызываются). Самопроверка на файле с тремя заведомыми ошибками находит все три.
